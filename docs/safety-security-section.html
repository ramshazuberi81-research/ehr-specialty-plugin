Safety, privacy and security

Research prototype. Fake patients only. Not for clinical use. It has not been security-reviewed or regulatory-reviewed, and it must never be pointed at real patient data.

Clinical safety: how it is designed
  • A human stays accountable. The software suggests and files; a clinician confirms anything uncertain.
  • Never guesses silently. Uncertain input becomes a visible suggestion with a review flag.
  • Never drops or "fixes" data. Unknown codes go to a general section; implausible lab values go to review.
  • Shows its source. Every summary line cites the record it came from; gaps say "not recorded".
  • Shows nothing rather than something wrong. No card if the specialty is unknown or nothing is recorded.

A draft hazard log lists 12 risks (for example wrong specialty routing, over-trust in the summary, wrong patient selected, and a model misreading a note). Every row still needs a named clinical owner, and nothing in it means the software is safe for clinical use. See the repository for the full safety case.

Privacy: what this demo does and does not do
  • Everything runs in this page with synthetic data. Typing never leaves your device.
  • The sign-in on this page is simulated. A real product needs real login, a second patient identifier and consent handling.
  • Voice uses your browser's speech service, which may send audio to its vendor. Use typing if that matters to you.
  • The optional plain-language layer sends only the request text to a model API. Real data would need a data-processing agreement and de-identification first.
  • No protected health information handling, encryption at rest or consent logic exists yet.
Security: controls in the code
  • Webhooks fail closed if the shared secret is unset, and the secret is compared in constant time.
  • Optional signed-token (SMART) login towards the FHIR server, and optional checking of the EHR's signed token on the CDS Hooks endpoint.
  • Dependency and code scans (pip-audit and bandit) run on every push and weekly.
  • Request bodies and clinical content are never logged.
  • Docker Compose publishes ports on localhost only.

Found a vulnerability? Please report it privately through the repository's Security tab (Report a vulnerability). Do not open a public issue, and never include real patient data.

Before any pilot: a named clinical safety officer signs off the specialty table, the site approves governance and privacy, real authentication and audit logging are added, and the tool runs in shadow mode first.
